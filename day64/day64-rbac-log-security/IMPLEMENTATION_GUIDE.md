## Learning Progression: From Authentication to Authorization

### Phase 1: Understanding Core Security Concepts (15 minutes)

**Authentication vs authorization**

- **Authentication** answers “Who are you?” Users log in with username/password; the backend verifies credentials and issues a **JWT**.
- **Authorization** answers “What can you do?” Each request carries the JWT; the **RBAC engine** checks whether the user’s **roles** allow the requested **action** on the **resource** (log namespace / service name).

**JWT token flow (as implemented)**

- Payload includes `user_id`, `username`, `roles`, `exp`, `iat`.
- Tokens are signed with **`JWT_SECRET_KEY`** (never committed). The backend loads `backend/config/.env` (and optional `backend/.env`) via `python-dotenv` inside `AuthService`.
- `deps.get_current_user` validates the `Authorization: Bearer <token>` header for protected routes.

**Role-based permission model**

- Policies are stored as strings like `logs:read:application.*`, with denials like `!logs:read:*.financial`.
- The engine builds a check string **`logs:<action>:<resource>`** and matches it against role permissions using wildcard regex (not `read:resource`).

### Phase 3: Authentication Service Implementation (20 minutes)

**Key file:** `backend/src/auth/auth_service.py`

- **`authenticate_user`**: looks up demo users in memory, verifies password with **bcrypt**.
- **`create_access_token` / `verify_token`**: JWT encode/decode with **`JWT_SECRET_KEY`**.
- If `JWT_SECRET_KEY` is missing, `AuthService` raises **`RuntimeError`** at construction time.

**First-time secret**

- **`start.sh`** creates `backend/config/.env` with a random `JWT_SECRET_KEY` if the file does not exist.
- Copy **`backend/config/.env.example`** → **`backend/config/.env`** and set your own secret for manual setups:

```bash
openssl rand -hex 32   # paste into JWT_SECRET_KEY=...
```

**Pytest**

- **`backend/tests/conftest.py`** sets `JWT_SECRET_KEY` for tests so `pytest` does not need a `.env` file.

**Password hashing sanity check** (optional)

```bash
python3 -c "
import bcrypt
p = b'admin123'
h = bcrypt.hashpw(p, bcrypt.gensalt())
print(bcrypt.checkpw(p, h))
"
```

### Phase 4: RBAC Engine Development (25 minutes)

**Key file:** `backend/src/rbac/rbac_engine.py`

**Permission pattern (important)**

- For a request, the engine uses:

  ```text
  permission_pattern = f"logs:{action}:{resource}"
  ```

  Example: action `read`, resource `application.auth` → `logs:read:application.auth`, matched against policies like `logs:read:application.*`.

**Role policies**

- In-code `role_policies` for `administrator`, `developer`, `analyst`, `support` with `permissions` and `restrictions` (including `!` denials and context tags such as `aggregated_only:true`).

**Testing RBAC from the repo**

```bash
cd backend
python3 -m venv venv && ./venv/bin/pip install -r requirements.txt
./venv/bin/python -m pytest tests/test_auth.py::test_rbac_permissions -v
```

Or interactively (set `JWT_SECRET_KEY` if you instantiate `AuthService`; RBAC tests only need `RBACEngine`):

```bash
cd backend
PYTHONPATH=. ./venv/bin/python -c "
from src.rbac.rbac_engine import RBACEngine
e = RBACEngine()
print('admin:', e.check_permission(['administrator'], 'logs.sensitive', 'read')['allowed'])
print('dev financial:', e.check_permission(['developer'], 'logs.financial', 'read')['allowed'])
"
```

### Phase 5: API Integration and Middleware (20 minutes)

**Shared state and dependencies**

- **`backend/src/shared.py`**: single instances of `AuthService`, `RBACEngine`, and **`AuditService`** so middleware, log routes, and admin routes share one audit trail.
- **`backend/src/deps.py`**: **`get_current_user`** dependency (HTTP Bearer + `auth_service.verify_token`).

**Key file:** `backend/src/main.py`

- Registers routers: `/api/auth`, `/api/logs`, `/api/admin`.
- **HTTP middleware** records each request to **`audit_service.log_access`** (user resolved from JWT when present, else `anonymous`).
- Adds `src/` to `sys.path` so `python src/main.py` works from `backend/`.

**Protected log API:** `backend/src/api/log_api.py`

- Uses **`Depends(get_current_user)`**.
- Calls **`rbac_engine.check_permission`** before search/export.
- When no `service` query param is passed, **default resource** depends on role (e.g. administrator → `*`, developer → `application`, analyst → `business` for read / `analytics` for export) so non-admins are not forced through a pattern they do not own.

**Admin API:** `backend/src/api/admin_api.py`

- Endpoints such as **`/api/admin/audit-summary`**, **`security-events`**, **`rbac-policies`**, **`system-status`** (administrator role required).

**Run the backend**

```bash
cd backend
# Ensure backend/config/.env exists (or export JWT_SECRET_KEY)
./venv/bin/python src/main.py
# Health: http://127.0.0.1:8000/health
# Docs:   http://127.0.0.1:8000/docs
```

**cURL examples**

```bash
# Login
curl -s -X POST http://127.0.0.1:8000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'

# Search (replace TOKEN)
curl -s -H "Authorization: Bearer TOKEN" \
  "http://127.0.0.1:8000/api/logs/search?limit=10"
```

### Phase 7: Audit Logging and Compliance (15 minutes)

**Key file:** `backend/src/audit/audit_service.py`

- **`log_access`**: append-only in-memory audit entries (timestamp, user, URL, method, status, duration, IP).
- **`log_security_event`**: failed logins, etc.
- **`get_audit_summary`**: aggregates used by **`GET /api/admin/audit-summary`**.
- **`shared.py`** seeds a small demo audit trail so fresh admin dashboards are not empty; **`scripts/demo.sh`** (invoked from **`start.sh`**) performs live API calls to add traffic.

**Verify audit APIs**


### Phase 8: Operations, Docker, and Cleanup (20 minutes)

**Process control (project root)**

| Script        | Purpose |
|---------------|---------|
| **`start.sh`** | Ensures venv + `node_modules`, creates `.env` if missing, frees ports **8000/3000**, starts backend + frontend, runs **`scripts/demo.sh`**. |
| **`stop.sh`**  | Stops PIDs from `.backend.pid` / `.frontend.pid`, kills listeners on 8000/3000, stops `react-scripts`. |
| **`cleanup.sh`** | Runs **`stop.sh`**, **`docker compose down -v`** for this repo’s `docker-compose.yml`, Docker prune (containers/networks/images/build cache), removes **`backend/**/__pycache__`** and **`.pyc`**. Set **`CLEAN_ALL_UNUSED_IMAGES=1`** to also `docker image prune -a`. |

**Docker Compose**

```bash
docker compose up --build -d   # from project root
docker compose ps
curl -s http://127.0.0.1:8000/health
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3000/
```

Backend image uses **`PYTHONPATH=/app/src`** in the Dockerfile so imports match local layout.

## Verification Checklist

### Authentication

- [ ] Login returns `access_token` and `user_info`.
- [ ] Invalid credentials return **401**.
- [ ] Protected routes without token return **401**.
- [ ] Passwords verified with bcrypt; JWT signed with env secret.

### Authorization

- [ ] Policies use **`logs:<action>:<resource>`** matching.
- [ ] Administrator can access broad log operations; developer/analyst restricted by role defaults and filters.
- [ ] **403** when RBAC denies access.

### Audit

- [ ] Middleware writes access entries to the **same** `AuditService` instance admin queries.
- [ ] Security events recorded for failed login (and similar).
- [ ] Admin audit summary reflects traffic (including demo seed / `demo.sh`).

### Frontend

- [ ] Login / logout and token persistence.
- [ ] Protected routes redirect unauthenticated users to `/login`.
- [ ] Admin-only API calls fail gracefully for non-admin (403).

### Operations

- [ ] **`start.sh`** / **`stop.sh`** work from project root.
- [ ] **`.env`** never committed; **`.gitignore`** respected.
- [ ] **`cleanup.sh`** stops stack and prunes Docker + Python cache as documented.

## Differences From Generic Tutorials

- **No hardcoded JWT secret** in source; use **`JWT_SECRET_KEY`** in `backend/config/.env`.
- **No API-key minting endpoint** in this version; authentication is JWT-centric.
- **Singleton services** in **`shared.py`** — do not instantiate separate `AuditService` per module.
- **RBAC check string** is **`logs:…`**, not **`read:resource`**.
- **React** uses **`SafetyCertificateOutlined`** (or similar) for icons supported by your **`@ant-design/icons`** version — avoid non-exported icon names.
